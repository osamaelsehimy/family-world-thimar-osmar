# Family World QA audit — 15 November 2026

## Scope and safety
This audit used the GitHub feature branch and the connected Family World Supabase project. Database checks were read-only except for two additive, idempotent migrations and rollback-only transaction tests. Test transactions were explicitly rolled back; no test invitation, test account, approval, game room, project, friend request, game session, or points award was committed.

## Verified production database state
- 11 profiles: 7 active, 4 pending.
- 8 Auth users email-confirmed, 3 unconfirmed.
- All 11 profiles have a permanent member code and guardian-attestation timestamp.
- One active account has the trusted osmar_admin app_metadata role.
- Admin pending-members RPC returns 4 pending records. Profile RLS isolation passed: a normal member sees only their own profile (1 row), while the OSMAR admin sees all 11.
- 10 OSM and 1 TRU invitation codes are currently usable; 7 are exhausted.
- Three legacy profiles have no referral row. Their membership records and member codes were preserved.
- Before repair, 6 of 8 referral rows were misclassified in the admin directory because the default admin_referral_label='TRU' took precedence over the actual referral type.

## Fixes applied
1. Applied the existing member profile/avatar migration and the new referral/RLS/performance migration to Supabase. Both are recorded in migration history.
2. Corrected osmar_member_directory to use coalesce(r.referral_type, p.admin_referral_label, 'UNCLASSIFIED'). Post-fix check: **0 mismatches across all 8 referral rows**.
3. Combined profile and apartment-design read policies and optimized JWT lookups.
4. Added indexes for the four foreign keys flagged by the database performance advisor.
5. Hardened OSMAR Admin UI actions: input limits, clipboard feedback/fallback, and try/catch/finally handling so network failures do not leave the interface stuck.
6. Restored missing authentication, trusted-membership, friend-request, and unified 3X read-policy migration source files. Renamed existing migration files to the exact versions recorded in Supabase. The repository now contains all 24 migration versions in the live migration history.

## Rollback-only integration tests passed
- Admin invite creation; non-admin invite creation correctly denied.
- Signup trigger: valid invitation creates a pending profile, permanent FW- member code, referral row, and increments the invitation once.
- Invalid invitation and missing guardian affirmation are rejected without consuming the invitation.
- Admin pending queue and membership approval RPC.
- Admin points award.
- 3X: complete all required tasks → submit → admin approve → 100-point award visible to the member.
- Apartment design: create and update a valid 100-cell design through the member RLS policy.
- Friends: send → accept → remove, including network visibility.
- Domino lobby: create → join → host leaves → host transfers → final player leaves → room cleanup.
- Local game-session insert and member dashboard aggregate view.

## Advisor results after the repair
- Performance advisor: no remaining missing-FK-index, RLS-initplan, or duplicate-permissive-policy findings. It reports 14 unused indexes at INFO level; do not remove them until production query volume is sufficient to judge usage.
- Security advisor: two INFO findings for RLS-enabled tables in the non-exposed private schema with no policies. This is intentional default-deny access.
- Security advisor still reports 17 authenticated-callable SECURITY DEFINER functions. The inspected RPCs are intentionally called by authenticated clients and contain explicit admin, active-member, ownership, or participant checks. Keep these checks and search_path=''; do not blindly revoke authenticated execution.
- **Leaked-password protection is disabled** in Supabase Auth. Enable it in Authentication → Settings → Password Security before public launch.
- The avatars bucket is public. Do not upload children's photos or sensitive images. Decide whether member avatars should remain public or move to signed/private delivery before broad family rollout.
